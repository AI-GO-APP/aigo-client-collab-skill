# Issue 格式與研究模式

兩種 issue，格式固定，讓客戶的 AI 與工程師的 AI 都讀得穩：

| 種類 | 誰開 | 標籤 | 用途 |
|---|---|---|---|
| 需要技術支援 | 客戶的 AI（客戶看過草稿） | `需要技術支援` | 碰到紅線或卡關，交給工程師 |
| 研究任務 | 工程師 | `研究任務` | 請客戶（和他的 AI）研究、訪談、整理業務規則或需求，結果回貼到 issue |

標籤不存在時先建立：

```bash
gh label create "需要技術支援" --color D93F0B --description "客戶協作：交給工程師處理" 2>/dev/null || true
gh label create "研究任務" --color 1F80FF --description "客戶協作：請客戶與 AI 研究後回覆" 2>/dev/null || true
```

**兩種 issue 都不寫真實個資、客戶資料、薪資、密碼、金鑰。** 需要範例時用虛構資料或描述（「一位 3 月到職的員工」）。

## 一、需要技術支援（客戶 → 工程師）

標題：`【需要技術支援】<一句話講要做什麼>`，例：`【需要技術支援】請假單核准後要通知申請人`

```markdown
## 客戶想要的（白話）
<用客戶的話寫：誰、在哪個畫面、做什麼、之後要看到什麼>

## 已經問清楚的
- 誰會用：
- 在哪裡用：
- 希望的結果：
- 例外情況：

## 為什麼交給工程師
<碰到哪一條紅線，或卡在哪裡；不確定就寫「不確定是不是需要工程師，請判斷」>

## AI 已經查到的
<相關程式位置（檔案路徑）、相關決策編號、試過的做法與結果、錯誤訊息（去掉個資）>

## 目前狀態
- 有沒有改到一半：<沒有／有，存在分支 `xxx`，尚未上線>
- 正式版有沒有受影響：<沒有／有，說明>

## 客戶接下來可以做的
<例：「先不用做什麼，等工程師回覆」或「這段期間請先用 Excel 記」>
```

開法：

```bash
gh issue create --title "【需要技術支援】…" --body-file <草稿檔> --label "需要技術支援" --assignee <技術窗口>
```

技術窗口寫在專案 `AGENTS.md` 的「客戶協作」一節；沒寫就不指派，並在內文最後加一行「（專案尚未設定技術窗口）」。

## 二、研究任務（工程師 → 客戶）

工程師開 issue 時照這個格式寫。**「給 AI 的指令」是客戶的 AI 唯一要照做的區塊**，其他是背景。

標題：`【研究任務】<要研究的事>`，例：`【研究任務】整理事務所現在的加班申請與核准方式`

```markdown
## 背景（給客戶看的白話）
<為什麼要研究、研究完會拿來做什麼>

## 要回答的問題
1. …
2. …

## 已經知道／已經排除的
<工程師已經查過的，不用再查>

## 給 AI 的指令
- 研究方式：<訪談客戶／讀程式與文件／整理客戶提供的檔案／混合>
- 要讀的地方：<檔案路徑、文件、相關 issue>
- 要問客戶的：<問題清單，或「依要回答的問題自行訪談」>
- 不要做的：<例：不要改程式、不要上線>
- 交回格式：照 aigo-client-collab 的「研究結果」格式；另外需要：<表格、流程、範例…>

## 期限
<希望什麼時候前回覆；沒有就寫「不急」>
```

## 三、研究模式流程（客戶貼了研究任務的網址）

1. **讀**：`gh issue view <網址> --comments`。讀不到（權限、網址錯）→ 跟客戶說原因，請他確認網址或找工程師開權限。
2. **確認範圍**：用三句白話跟客戶講「工程師想知道什麼、我們要怎麼查、大概要問你幾題」。
   issue 不是研究任務格式也沒關係，照內容判斷；看不懂要做什麼就問客戶，或在 issue 留言請工程師補（客戶同意才留）。
3. **研究**：
   - 訪談客戶：一次一題，用業務的語言問，例：「同事要加班時，現在是先口頭說，還是先填單？」
     客戶說「要問別人」就記成待確認，繼續問下一題。
   - 讀程式與文件：照「要讀的地方」讀；講程式的行為時以實際程式為準。
   - 客戶提供檔案（Excel、PDF、截圖）：只取需要的結構與規則，**不把裡面的真實資料抄進結果**。
4. **整理**成下面的格式，**先給客戶看**，問「這樣寫對嗎？有沒有要改的？」
5. **回貼**：客戶說可以才留言：`gh issue comment <網址> --body-file <結果檔>`。回報留言網址。
6. **不順手實作**：issue 沒要求就不改程式。結果裡有建議做法時，問客戶要不要接著走功能流程。

### 研究結果格式

```markdown
## 研究結果（客戶確認過）

### 結論
<三句以內回答 issue 的問題>

### 逐題回答
1. <問題> → <答案>（來源：客戶訪談／程式 `路徑`／客戶提供的檔案）
2. …

### 業務規則與例外
<整理出來的規則；例外情況各一句>

### 還不確定的
<客戶說要問別人、或查不到的；寫誰可以回答>

### 建議（若有）
<建議做法，標明是 AI 的建議>
```
